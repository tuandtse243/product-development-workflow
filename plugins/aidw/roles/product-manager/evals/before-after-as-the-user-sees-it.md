## Input

The discovery record of a clinic booking change says: patients phone the front desk to book and often wait on hold;
the receptionist writes each booking in a paper diary; moving an appointment takes a second call; the clinic wants
patients to book and reschedule on their phones. During the interview the user also wondered whether the clinic's
phone system could send an event when a call is missed, and whether bookings should be cached on the phone. There is
no Existing System Report: the clinic has no software today. Draft the Analysis parts you own.

## Criteria

- must write `## Before / After` with `### Before` and `### After`, each 3 to 6 `- ` lines
- must write Before from today's workaround (phone calls, waiting on hold, the paper diary), in the user's words
- must not name a table, endpoint, component or library in any Before or After line
- must list the phone-system event and the caching question under `### Deferred to architecture` as `- DA1:` and `- DA2:` lines, not answer them itself
- must not turn either technical question into a requirement or a question for the user
